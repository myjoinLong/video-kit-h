# 07 · 常见问题

**Q：换一个完全不同类型的口播稿，要改渲染代码吗？**
不用。复制一期目录或 `npm run episode:new`，改 `episode.json` 的 `chapters`（正文、时间码、分镜、元素）和 `anchors.lrc`（画面要点），跑 build → render → verify → archive 即可。只有要新增一种信息图/转场时才动内核。

**Q：能自动生成"跟稿子语义精确对应"的画面吗？**
不能，也不假装能。`shots[].elements` 是通用信息图组件，选哪张、写哪些要点必须人指定。自动的是节拍网格、字幕卡拆分、切镜、转场、色彩弧、两版排版与验收。这条边界写进了 README。

**Q：为什么成片是静音的？**
你后期补录旁白。成片内嵌的是**精确等长的静音 AAC 轨**，按 `narration-cues.json` 的 `in/out` 替换即可。画面内手绘文字已经烧进画面，不需要再叠字幕层。

**Q：9:16 能直接从 16:9 裁出来吗？**
不建议，也没这么做。横版信息图会被裁掉左右、字卡会挤成一团。9:16 是同一世界重新取景 + 竖版信息图重排 + 字幕带改 3 列网格，见 `docs/03`。

**Q：为什么两版各有 `generated/`？**
竖屏字幕卡多了 `bandCol/bandRow` 格位、字号按 `kfScale` 收窄，规格数据也标记了 `meta.layout`。共用一份会让其中一个画幅的排版退化。

**Q：中文显示成方框 / 豆腐块？**
`src/core/font.mjs` 会探测系统楷体。Windows 找 `simkai` / `STKAITI`，macOS 找 `Kaiti SC`，Linux 找 Noto CJK；都没有时退化到通用字体。最稳妥是放一份有权分发的中文字体到 `assets/fonts/` 并在配置里指定。

**Q：build 报「chapter pace outside 120–300」？**
该段字数与时长不匹配。缩短正文或延长该段（同时调整后面章节的 `in/out` 保持连续）。参考 220 字/分钟。

**Q：verify 说「纯黑 / 纯白像素」不为 0？**
通常是外部叠加了字幕层、水印或片头黑场。本内核只在色板内取色，不会自己产生纯黑白。

**Q：成片为什么不进 Git？**
体积大（首期两版各约 110 MB），且可能含你放入的授权音频。留痕靠 `manifest.json` 里的 SHA-256 与 ffprobe 事实，本地 `episodes/<slug>/out/` 保留原件。

**Q：能只做一版画幅吗？**
可以，跑对应那份 `project.json` 即可。但 `verify-delivery.mjs` 与 `archive-episode.mjs` 默认检查两版；缺的那版会在 manifest 里标 `pending`，不会伪造成已交付。

**Q：首期 16:9 成片是重渲的吗？**
不是，是已交付版本的原文件复制（哈希一致）。新项目的 16:9 字幕卡数据与原工程逐字节一致、横屏渲染路径未改，因此可以按 `manifest.json` 里的命令原样复现；`notes.honesty` 里也写明了这一点。

**Q：能用我的一段人声生成整条旁白吗？**
不能"克隆"——那需要本地部署 GPT-SoVITS / CosyVoice / fish-speech 一类模型及权重，本项目不含。但样音很有用：`python tools/check-recording.py --episode <期次> --take <样音> --sample --chars <字数>` 会测出你的真实语速、停顿与电平，并给出每章建议字数；据此改 `episode.json` 重新编译，时间码就贴合你的说话习惯。录完整条后用 `--mux` 自动对齐替换音轨。详见 `docs/08-音频与配音.md`。

**Q：参考音是 AI 读的，能直接当配音发布吗？**
不建议。它是**节奏标尺**：逐章贴合时间窗，用来听语速和换气，也可临时试看。情感、重音、专有名词读法都不可控，商用还要确认在线 TTS 服务条款。发布请用自己录的人声。

**Q：GitHub 推送失败？**
多为网络代理问题。可试 `git -c http.proxy= -c https.proxy= push origin main`，或用 `git bundle create video-kit-h.bundle --all` 生成离线包，到本地 `git fetch` 后合并。
