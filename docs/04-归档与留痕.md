# 04 · 归档与留痕

> 目的：三个月后还能回答「这支片子当时是怎么做出来的、验收过了没、哪些没做」。

## 留痕三层

1. **源**：`episode.json` + `anchors.lrc` —— 稿子与分镜的唯一真相，进 Git。
2. **派生物**：`generated/`、`generated-9x16/`、旁白三件套、两份 `project.json` —— 全部进 Git，别人 clone 后能直接复现。
3. **事实**：`manifest.json` + 两版联系表 + 验收报告 —— 进 Git；成片本身只留在本地 `out/`，不进 Git。

## `manifest.json` 记什么

| 块 | 内容 |
|---|---|
| 基础 | `episode / date / title / topic / tags / status / archivedAt` |
| 参数 | `duration / fps / bpm / offset / chapters / shots` |
| `narration` | 补录方式、总字数、各章语速、三份稿子路径 |
| `layouts[]` | 每版：成片路径、字节数、**SHA-256**、ffprobe 事实（时长/编码/画幅/帧率/帧数/音轨）、联系表路径、验收结果、配置路径 |
| `generatedFiles[]` | 8 份生成数据的 SHA-256 |
| `commands[]` | 完整复现命令序列 |
| `notes` | `episode.json` 里的如实说明（未完成项、素材来源、下一步） |
| `gitCommit` | 归档时的 Git HEAD（若可用） |

**成片不入库，但哈希在库里**：任何一份本地成片都能用 `sha256sum` 与 manifest 对上，防止"改过却说没改"。

## `INDEX.md`

由 `tools/archive-episode.mjs` 扫描所有 `episodes/*/manifest.json` 自动重生成，列出：日期、期次链接、标题、时长、章节/分镜数、两版画幅、验收状态、manifest 链接。

**不要手改 INDEX.md**，跑一次归档脚本就会刷新。

## 归档脚本还会做

- 从**最终 MP4**（不是渲染源）按每镜 55% 位置抽帧，拼两版 10 镜联系表 `out/contact-16x9.jpg` / `contact-9x16.jpg`
- 读取两版 `out/verify-report-<layout>.json`，把 `passed/total` 写进 manifest
- 记录当前 Git HEAD

## 补归档 / 重新归档

```bash
# 成片重渲或报告更新后，重跑即可（覆盖 manifest、刷新 INDEX）
node tools/archive-episode.mjs --episode episodes/<slug>
```

若某一版成片缺失，脚本会在 manifest 里把该版标成 `pending`（`film: null`），不会伪造数据；`INDEX.md` 显示「⚠️ 待验」。

## 每期必写的如实说明

`episode.json` → `notes.honesty`，至少包含：

- 是否做了全片连续试看试听（通常只做抽帧目视与机检）
- 旁白是否已录（首期为后期补录）
- 音频 / 字体 / 素材的授权状态
- 哪些判据是人工确认的（艺术连贯性、线条手感、授权）
