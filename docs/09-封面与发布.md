# 09 · 封面与发布

> 一支片子做完、要发到抖音/视频号时，用 `tools/make-cover.mjs` 出封面。
> 封面不是"截一帧加字"：片中字幕会和封面标题打架，信息图整页小字也不适合当封面。

## 两种底图

| `--kind` | 底图 | 适用 |
|---|---|---|
| `music` | 用本片渲染内核重渲一帧，**关掉片内字幕** | 音乐卡点片、画面主体明确的片子 |
| `explainer` | **封面专用构图**：三张手绘规格卡 + 主角 + 纸飞机 | 口播/讲解片（片中帧是整页信息图，小字太多） |

两种都沿用同一套 13 色板、纸纹、墨线毛边与楷体手写感，不引入新素材。

## 抖音安全区（硬约束）

1080×1920 画布上，所有文字必须在 **x ≤ 856 / y 252–840**：

- 右侧约 200 px 被头像/点赞/评论/分享/音乐盘覆盖；
- 底部约 450 px 被文案、话题与进度条覆盖，不放任何关键信息；
- 个人主页九宫格会把 9:16 裁成 3:4。脚本额外输出 `*-3x4.png`（1080×1440，从 y=216 裁到 1656，比居中略偏上，给集数印章留白）。

印章、两行大标题、数字条、标注贴纸与主体在两种画幅里都必须完整。

## 版式

```
y 252–310   集数 / 栏目标签（陶土深印章，宽度按文字自适应）
y 336–636   主色刷带（暖黄 / 天蓝，带干笔飞白）+ 两行大字
y 654–726   数字钩子（奶白纸条，不加会穿字的下划线）
y 760–826   一句手写批注 + 短笔触（不要长箭头，容易指错地方）
y 840+      只留画面主体，不再放字
```

主标题用楷体 + 奶白粗描边 + 陶土深错位重影，保证在信息流小图里也读得清。

## 命令

```bash
# 讲解片（封面专用构图）
node tools/make-cover.mjs --engine ./src/render.mjs --kind explainer \
  --config episodes/<slug>/project-9x16.json --time 5 --out out/cover.png

# 音乐片：脚本放到该片工程 tools/ 下，加环境变量
AM_LAYOUT=vertical node tools/make-cover.mjs \
  --engine ./src/render.mjs --kind music --time 119.5 --out out/cover.png
```

> 脚本与渲染内核必须加载**同一份** `@napi-rs/canvas`：在同一个工程目录里运行，不要跨工程动态 import，否则两份原生模块同进程会崩。

## 发布文案的规范

- 标题走账号既有的连续剧结构（第 N 集 / 合集名），接上一期而不是另起炉灶。
- 数值要真实、能核对；不写"一键出片""AI 全自动"这类夸大表述。
- 互动钩子落在片中一个具体时间点，方便回复时带节奏。
- 音乐 / 字体 / 第三方素材的授权署名写进置顶评论。
- 平台若要求「内容由 AI 生成」声明，发布时勾选。

## 如实说明

封面只做静帧目视与尺寸/哈希机检，**没有在 App 内实机上传验证**；不同机型的信息流 UI 遮挡范围略有差异。发布素材与稿件留在本地交付目录，不进 Git；生成器与规范入库，`manifest.json` 记文件哈希留痕。
