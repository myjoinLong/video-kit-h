# 08 · 音频与配音（参考音 / 真人录音 / 人声样音）

> 本项目的成片**默认自带精确等长的静音 AAC 占位轨**，不含任何第三方音频。
> 旁白有三种走法，按推荐度排序：**真人录音（交付） > AI 参考音（录制前听节奏） > 声音克隆（本项目不做）**。

---

## 1. 先说清楚三条边界

| 方案 | 能做什么 | 不能做什么 | 本项目是否具备 |
|---|---|---|---|
| **A. AI 参考音** | 用 edge-tts 把 `chapters[].narration` 读成一条 240 秒示范音轨，逐段贴合各自的时间窗；给你听语速、停顿、哪里该换气；也能临时顶替旁白试看 | 不是你的声音；情感、重音、专有名词读法不可控；**不是成片配音**，商用前还要查服务条款 | ✅ 已内置 `tools/build-voiceover.py` |
| **B. 真人录音** | 按 `narration-script.md` 逐字念，用点击轨找节奏，录完自动做时长/峰值/静音/分段检查，一键响度标准化并替换音轨 | 需要你自己录 | ✅ 已内置 `tools/check-recording.py` |
| **C. 声音克隆** | 用几十秒样音生成整段同音色旁白 | 需要本地部署 **GPT-SoVITS / CosyVoice / fish-speech** 一类模型及其权重，通常还要 GPU；且涉及声纹授权与伦理 | ❌ 本项目不含，也不代为承诺 |

**「给一部分我的人声，然后根据人声去做」能做到的部分**（`check-recording.py --sample`）：

1. 测你的**实际播讲语速**（字/分，按去掉首尾静音后的朗读跨度算，含句间停顿）、纯发声语速、平均停顿长度、峰值与响度。
2. 按你的真实语速反推：全稿在当前 240 秒窗口里够不够念、每章应该写多少字，给出逐章建议字数——据此改 `episode.json` 的 `chapters[].narration`，重新 `build-episode` 即可让画面时间码与你的语速对齐。
3. 把样音剪成每段开头的示范片段、生成录制提示与对轨模板。
4. 你录完整条之后，自动对齐、响度标准化、替换音轨出片并留痕。

**做不到的部分**：把这段样音"扩写"成 4 分钟同音色的旁白。这不是脚本能补的能力，需要模型。若以后你在本地装好了克隆模型，接入点很明确——把它的输出当成 `--take` 的文件喂给 `check-recording.py --mux`，后面的对齐、验收、归档链路一行都不用改。

## 2. 准备（一次性）

```bash
python -m pip install edge-tts numpy soundfile
# ffmpeg / ffprobe 需已在 PATH（本项目其余流程也依赖）
```

`edge-tts` 合成时会联网调用微软在线语音；**断网时**可以用 `--no-synth` 只生成点击轨，或用别的 TTS 把音频放进 `voice/segments/`，再让脚本按时间码拼接（当前版本默认走合成）。

## 3. 生成参考音（录制前听）

```bash
python tools/build-voiceover.py --episode episodes/<slug>
```

产出（都在 `episodes/<slug>/voice/`）：

| 文件 | 用途 |
|---|---|
| `reference-vo.wav` / `.mp3` | 完整 240.000 秒示范朗读，采样级对齐 `chapters[].in` |
| `segments/01..07.mp3` | 逐段文件，录哪段听哪段 |
| `click-track.wav` / `.mp3` | 90 BPM 点击轨：每拍一响、小节重音、每章开头双响。**不进成片**，录音时戴耳机听，录完删掉 |
| `voiceover-report.json` | 每段的目标语速、实际语速、时间伸缩量、警告 |
| `out/*-reference-vo.mp4` | 把参考音换进成片的**试看版**（视频流 copy，画面逐帧不变，原成片不被改动） |

可调参数：

```bash
--voice zh-CN-YunxiNeural     # 换音色（男声）；默认 zh-CN-XiaoxiaoNeural
--rate -10                    # 固定语速，关闭逐章自适应
--base-wpm 270                # 校准该音色的自然语速
--no-synth                    # 只出点击轨，不联网
--no-mux                      # 不生成试看版 MP4
```

**为什么逐章调速**：7 章时间窗不同（18/40/45/45/45/35/12 秒），稿子设计语速从 205 到 277 字/分不等。脚本按每章自己的窗口在**合成阶段**设语速，只对残差做 ≤ ±6% 的时间伸缩；这样听感自然，不会出现"为了填满窗口把整段慢放 20%"的失真。

**参考音的定位**：它是**节奏标尺**，不是成品。别拿它判断音色好不好，重点听"这段要在 45 秒里讲完 208 字，所以这里必须连着说"。

## 4. 录你自己的人声（交付）

1. 打开 `narration-script.md`——每章有**照念正文**、时间码、画面提示、字数与语速。
2. 戴耳机听 `voice/click-track.mp3`（或只看画面时间码），按章录；每章末尾留 0.5–1.5 秒呼吸，不要抢转场。
3. 建议每章单独存一个文件，最后拼成一条；或一次录完再按 `narration-cues.json` 的 `in/out` 微调。
4. 录完检查：

```bash
python tools/check-recording.py --episode episodes/<slug> --take ~/my-voice.wav
```

报告给出：时长差、峰值/RMS、削波样本、最长静音、停顿次数，以及**逐章有声时长占比**（过空或过满会点名让你重录该章）。

5. 一键替换音轨出片：

```bash
python tools/check-recording.py --episode episodes/<slug> --take ~/my-voice.wav --mux
```

自动补齐/裁到 `episode.duration` 精确长度（不改动你的源文件）、`loudnorm` 到 −16 LUFS、AAC 320k、视频流 copy，为每个画幅生成 `*-voiced.mp4`。加 `--no-loudnorm` 可跳过响度处理。

> 若只给了**一小段样音**（不是整条录音），加 `--sample --chars <样音里的字数>`，工具会输出语速与逐章建议字数，不出成片。

---

## 5. 音频的归档留痕

- `voice/voiceover-report.json`、`voice/recording-report.json`、`voice/sample-analysis.json`、`narration-*`、`manifest.json` 入库。
- `*.wav` / `*.mp3` / `*.mp4` 一律**不入库**（体积大、且真人声音属于个人数据）；`manifest.audio` 记文件名、时长、引擎/音色、SHA-256 与验收结论。
- 成片原件留在本地 `episodes/<slug>/out/`，哈希在库里，改没改一查就知道。

---

## 6. 合规

- 参考音由在线 TTS 生成，**仅用于内部对轨与试看**；对外发布前确认所用服务条款是否允许该用途。
- 真人录音是发布时最干净的方案。
- **不要拿别人的声音做克隆**；声纹属于个人生物特征，需本人明确授权。
- 本项目模板自身不含任何第三方音频；音乐片项目另行处理词曲与录音制品授权。
