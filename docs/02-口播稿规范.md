# 02 · 口播稿规范

## 唯一数据源：`episode.json`

| 字段 | 作用 | 约束 |
|---|---|---|
| `id` / `date` / `title` / `topic` / `tags` | 归档索引用 | `id` 建议 `YYYY-MM-DD-slug`，与目录同名 |
| `duration` / `fps` / `bpm` / `offset` | 全片节拍 | 首期 240 s / 24 fps / 90 BPM / 0.400 s |
| `softEndingAt` | 片尾减速收束起点 | 默认 `duration − 1.6` |
| `closingLine` | 最后一张中央巨化卡文字 | 8–12 字最佳 |
| `narration` | 补录方式、参考语速、说明 | `silentPlaceholder: true` 时成片内嵌静音轨 |
| `style` | 色板、沸腾频率、交互、竖屏信息图开关 | 见 `docs/03` |
| `layouts.16x9 / 9x16` | 主角位置、字幕带、输出路径、字号倍率 | 两版都必填 |
| `chapters[]` | 旁白正文 + 时间码 + 画面说明 | 首尾相接覆盖全片 |
| `shots[]` | 分镜（边界、镜头、元素、色彩弧、转场） | 首尾相接覆盖全片 |
| `notes.honesty` | 未完成 / 需人工确认的事 | 必填，进 manifest |

## 章节怎么写

```json
{
  "id": 3,
  "in": 58.0,
  "out": 103.0,
  "title": "关键点 2+3 · 规格化提示词与风格边界",
  "shots": [4, 5],
  "screen": "规格文档逐行高亮 → A/B/C/D 四类风格边界表 → 13 色色板",
  "narration": "……"
}
```

- **字数**：中文口播约 **220 字/分钟**。编译器按 `字数 ÷ 时长 × 60` 算语速，超出 **120–300** 会报错。
  首期七段实测 205 / 219 / 223 / 227 / 274 / 277 / 213 字每分。
- **时间码**：相邻章节 `in == 上一段 out`，最后一段 `out == duration`。转场落在章节或分镜边界上。
- **结尾留白**：最后一句在 `softEndingAt` 之前收住，留 1–2 秒余韵，别抢收束。
- **screen 字段**：写"观众看到什么"，不是制作说明。它会出现在给主播的稿子里，方便对齐语气。
- **不要写"适当 / 自然 / 好看"**：这与片子讲的方法论自相矛盾；写具体画面、具体数字。

## 画面内要点：`anchors.lrc`

```
[ti:怎么用 AI 出一份优质的应用动画视频]
[00:02.060]先拆音频 别先想画面
[00:10.500]三个数决定后面一切
...
```

- 一行一条，时间码精确到毫秒；编译器按时间排序、过滤超片长的行。
- 短句 4–12 字；每行会被拆成 **2–3 张独立手绘分卡**，按细分拍错开入场。
- 这些字是**画面元素**，不是字幕轨：和角色、道具用同一套笔触、墨线、水彩、纸纹与 12 次/秒沸腾。
- 同一时刻最多 3 张卡；首尾留出安全边距；避开主角眼睛保护区。
- 不要在这份文件里写旁白全文——那是 `chapters[].narration` 的职责。

## 编译器自动做的四件事

1. `narration-script.md`：给主播的可打印稿（章节表 + 时间码 + 画面提示 + 录制提示）
2. `narration-cues.json`：每章 `in/out`、字数、正文，供剪辑软件或后续 TTS 对轨
3. `narration.srt`：标准 SRT，直接拖进时间线
4. 语速自检：不合规直接拒绝生成

## 旁白补录

成片是 **240.000 秒精确等长的静音 AAC 轨**（AAC 数字静音实测约 −91 dB）。
录完后按 `narration-cues.json` 的 `in/out` 对齐，替换静音轨或另起一条配音轨即可。
**画面内手绘文字已烧进画面，不要再加字幕层。**
